# Phase 10 — PostgreSQL + Signal / Trade History

Phase 10 keeps the Phase 9 C++ strategy unchanged and adds persistent history.

## What is stored

- `market_signals`: every C++ engine result, including indicator values, bullish/bearish scores and active levels.
- `trade_plans`: bullish and bearish candidate plans generated by Phase 9.
- `trades`: paper/manual trades with entry, quantity, exit and realized P&L.
- `signal_events`: audit events such as `SIGNAL_GENERATED`.

## Setup

1. Install PostgreSQL and create a database named `trading_system`.
2. In `backend/.env`, set `DATABASE_URL`, for example:

   `postgresql://postgres:postgres@localhost:5432/trading_system`

3. Install dependencies from the project root:

   `npm install`

4. Run migrations:

   `npm run db:migrate --workspace backend`

5. Build the C++ engine as in Phase 9.
6. Start backend and frontend.

## API

- `GET /api/history/signals`
- `GET /api/history/plans`
- `GET /api/history/trades`
- `GET /api/history/analytics`
- `POST /api/trades`
- `POST /api/trades/:id/close`

Example filters:

`/api/history/signals?symbol=NIFTY&signal=BUY&limit=50`

`/api/history/trades?symbol=NIFTY&status=CLOSED`

## Important

Trades in Phase 10 are paper/manual records. No broker orders are placed. Entry/SL/targets remain research levels until later execution phases add a dedicated position manager and broker integration.
